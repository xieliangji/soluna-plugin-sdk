# 专项执行证据契约设计

状态：待实现设计，尚未发布，不属于当前 `special/1.0` 的强制字段。本文定义下一版专项协议及集成测试的验收目标。正式启用前须在 SDK 同步类型、Schema、语义校验器和正常／故障夹具，再接入宿主、生成器及集成测试；不得把本文当作已可调用接口。

## 目标与所有权

专项插件必须交付足以追溯业务判定的执行细节。分析输入独立于 HTML 和插件 Reporter；模型分析不要求插件调用模型，也不允许分析结果反向修改原执行事实。

| 生产者 | 负责的事实 |
| --- | --- |
| Soluna | 从入口启动开始的配置、编译、插件身份／二进制摘要、设备与会话准备、每次关键字意图／反馈、退出、清理、报告与交付；资源接收确认及完整性 |
| 专项插件 | 测试目标、业务单元与轮次、分支条件及选择、重试原因、检查规则、预期／实际、领域指标及计算依据、业务清理要求与结果 |
| 分析器 | 读取冻结事实，输出带证据引用的发现、原因候选、缺失信息和建议；自身身份及所用快照摘要 |

宿主可以证明调用发生及反馈内容，不能代替插件解释业务意义。插件提供业务判定，不能覆盖宿主记录的执行中断、设备错误或清理失败。共享关键字证据由宿主记录一次，插件引用相应操作，不复制一份可能矛盾的结果。

## 公共记录与关联

以下为拟议字段；最终 wire 定义须随新协议发布，生成的插件项目不能自行重定义公共结构。

| 记录 | 必须表达的信息 |
| --- | --- |
| 执行身份 | 宿主分配的 executionId；建立 runId 后补关联；插件实例／版本／二进制摘要、冻结输入摘要 |
| 业务单元 | unitId、可选 parentUnitId、业务名称／目标、开始和终态；轮次、重试为不同单元或显式 attempt 身份 |
| 事件 | 版本、稳定 eventId、生产者、连续 sequence、类型、阶段、unitId／operationId 等适用关联、记录时间；实际采样时间与时钟来源分开 |
| 检查 | checkId、规则及版本、预期、实际、单位（适用时）、判定、证据引用；无法取得实际值时写明不可用原因，不能填零 |
| 分支 | decisionId、条件、所用观察／检查引用、选择的路径及理由、其它路径未执行原因；不声称所有路径均已覆盖 |
| 指标 | 名称、数值或不可用原因、单位、样本数、样本引用、计算规则／版本、纳入与排除口径 |
| 资源 | resourceId、类型／格式、来源、采集范围与时间、关联单元／操作、宿主确认的摘要和大小；完整、截断、缺失等状态及原因 |
| 证据缺口 | gapId、稳定原因分类、受影响阶段／范围／单元、详情、已知丢失数量或明确未知；即使执行失败也保留 |
| 终态清单 | 最后确认事件序号、业务单元及检查状态、所引用资源、已知缺口、领域结果 Schema／版本；宿主核对后另行给出完整性结论 |

预期值来自配置、业务规则或外部基准，并记录来源，不能把本次观察值复制成预期。检查规则没有数值预期时使用结构化规则，不强塞一个空预期文本。

执行完成情况、业务判定、证据完整性、清理结果和交付结果是不同维度。`not_matched` 不是通信失败，`unknown` 不是 `passed`，`not_run`／`skipped` 不是已覆盖。缺少足够证据时允许受限分析，但必须列出缺口；协议校验失败使集成测试失败，不抹掉已经观察到的业务结果。

私有扩展使用插件命名空间和独立 Schema 版本。字段说明须包含意义、单位、统计口径与判定规则，并随插件描述冻结；不要求所有专项使用相同领域结果模型。

## 持续上报与宿主确认

1. 插件通过 SDK 的类型化证据接口持续提交业务事件，不能等 Run 返回后才一次性提交全过程。SDK 接收当前运行／实例上下文，调用方不能随意指定另一次运行。
2. 宿主校验消息并持久化后才确认。序号重传必须内容一致，不重复计数；相同身份不同内容报冲突。最后确认序号供冻结时对账，RPC 返回成功本身不证明业务通过。
3. 关键字 SDK 调用自动关联当前业务单元及 operationId，反馈带可引用的宿主证据身份。宿主实际结果不可由插件自行声明替代。插件自行完成的外部业务观察标记为插件来源，并附原始资源或缺失原因。
4. 大段日志、页面树和样本存资源，通过有界分块传输或显式受控文件交接由宿主接收；不能把任意插件路径／URL 当作已交付证据。日志分片记录范围，截断必须可见，不能仅靠扩大 RPC 帧上限传输。
5. 崩溃、失联、取消或截止时间到达时，宿主保存已确认记录，并为在途调用、未闭合单元、缺失资源和未完成清理记录缺口；不伪造插件完成事件，不自动重放操作。
6. 证据通道背压、配额耗尽和写入失败要作为明确结果反馈。宿主无法持久化时不得继续宣称记录完整，应停止新业务并进入有界清理，尽可能保存可读故障信息。

事件序列用来检查生产者流；跨进程先后以请求／操作因果关系关联。耗时以同一时钟测量，未校准设备日志时钟不能直接与宿主时间相减。业务单元的重复运行及重试保留各次事实，不能覆盖前一次失败。

## 分析快照与报告解耦

执行与清理结束后，由宿主独立的结果／证据服务冻结分析快照，不依赖 Reporter 被调用或成功。启动／编译失败、没有 RunResult 或插件无法再次启动时，也须可生成含失败及缺口的分析输入。

快照包含版本、身份、输入摘要、来源描述、实际覆盖范围、截止序号、完整性、事实流及资源索引；资源由读取器按摘要、大小和读取预算验证。快照中的关联必须闭合，不能依赖插件内存或临时文件仍存在。

报告与分析是同一份冻结输入的独立消费者。报告／上传阶段继续记入外层证据，后续分析使用新快照及其摘要；不得回写旧快照。分析结果独立存储，带输入快照身份、模型／分析器版本、证据引用、事实与推断区别、缺失信息及处理建议。报告可以展示分析结果，分析也可单独读取。报告失败、分析失败均不改写原业务判定。

当前 special/1.0 的分析输入在宿主 `Reporter.Prepare` 中先于插件报告调用写入，可承受插件报告失败，但尚未满足这里要求的所有报告入口之外的冻结路径。迁移时必须搬到宿主结果终结阶段，并验证早期失败。

## 校验与集成测试要求

SDK 提供公共结构与纯校验器；Soluna 负责关联宿主真实记录的语义校验，测试 stub 使用相同校验入口。至少覆盖：

- 正常运行：每个业务单元闭合，检查／指标能追到输入与原始证据；正常完成且有业务失败也可以证据完整。
- 非法身份、序号断档、重复冲突、缺失或跨运行引用、资源摘要不符；事件发送成功但宿主未持久化不能算确认。
- 插件省略业务细节、伪造关键字成功、统计分母不含已失败轮次、未执行分支冒充已覆盖，必须暴露契约违规或不一致。通用校验检查结构和引用，领域统计另由插件提供已知样本与预期结果夹具；不能宣称通用 Schema 能证明任意业务算法正确。
- 分支、循环、多次重试、观察不可用、采集截断，能够还原实际经过而不是只留下最终 passed／failed。
- 插件在动作前／中／后崩溃，取消、清理失败、持久化失败与配额耗尽；保留已确认事实，明确未知与缺口。
- 启动、配置及编译失败仍有宿主证据；无报告／报告失败／新进程渲染时，分析输入仍可独立读取。
- 冻结快照之后的交付失败不改变旧摘要；分析输出引用不存在证据时拒绝接收。

集成测试验收可追溯性和协议行为，不能证明真实设备行为、任意业务结论或模型推断正确。

## 版本与落地边界

现行 special/1.0 的 Event.Data 是自由 JSON，Result 也没有上述强制证据终态。增加必填字段和强制语义属于破坏性升级，必须发布新协议及匹配 SDK；发布前确定版本号，不能只更新生成器或文档就宣称旧插件具备该能力。

旧插件可在明确支持的旧协议边界运行，其证据能力应标记为未声明／受限，不能伪造新版完整性通过。新插件通过 SDK 取得公共模型、上报客户端、校验器与开发指南，不生成项目内协议实现副本。类型化关键字接口、证据关联、宿主冻结和 stub 验收应作为同一个闭环交付；模型分析接入仍属于后续任务。
