# 协议导航

开发者和 Agent 共用[插件开发指引](development.md)。

| 类别 | 通信与生命周期 | 业务边界 |
| --- | --- | --- |
| UI 自动化能力 | [能力协议 1.0](ui-protocol.md) | Health、Execute、Shutdown；通过资源描述符读写事实 |
| OCR | 上述能力协议 | [OCR 契约](ocr-contract.md)：初始化、图片／ROI、文字与模型身份 |
| 日志断言 | 上述能力协议 | [日志契约](log-contract.md)：授权日志、私有规则、真假与执行失败 |
| 专项测试 | [special/1.0](special-protocol.md) | 配置编译、准备／执行／清理、Host 回调、独立结果及私有报告 |

Schema 位于 contracts，精确 Go 类型位于 pluginapi。SDK 维护通信与能力协议，生成项目直接实现 SDK 接口，只维护私有参数、业务、报告及测试。文中宿主操作链接仅供 Soluna 使用方式参考，插件编译不依赖宿主源码。

专项下一版证据边界见[执行证据契约设计](special-evidence.md)，包含插件业务事实、宿主确认、独立分析快照与集成测试要求；尚未作为 special/1.0 的强制协议发布。

## 扩展与版本

新增同类能力声明独立名称、版本、输入输出与错误分类；新增类别提供新的协议包、清单、宿主接入、生成模板和契约测试。不要向所有插件强塞同一生命周期，也不能只新增生成器目录却没有宿主支持。

进程协议版本、能力版本、配置／结果版本、SDK module 版本和插件版本分别管理。v0.1.0 抽取既有协议，未改变协议字节。专项首个稳定版前保持 V1 并精确匹配草案 revision；稳定后破坏性变化发布新协议并保留旧版本读取／执行边界；可选能力通过协商启用。

SDK 只依赖标准库，单独运行 go test -race ./... 与 go vet ./...。源码测试覆盖帧错误、并发响应、取消、OCR 资源边界、清单完整性和专项双向调用。宿主仍需独立执行真实生成项目的兼容验收。

当前迁移草案及实际能力见[专项协议](special-protocol.md)，完整设计见[V1 设计](special-design-v1.md)。
